# PocketGrid prototype protocol (v1)

All routes `/api`, JSON unless GET image. Coordinator default http://127.0.0.1:8787. Vite port 5173 proxies /api. ISO times replaced by Unix seconds in JSON. All credits are integer sandbox units, no cash value. Never send private inputs.

**V1 (GiPU) contract.** Items marked **(V1)** were agreed for the V1 release ([v1-plan.md](v1-plan.md)). Each account sees only its own jobs, images, events and devices, plus anonymous grid counts. Implementation status of every **(V1)** item is tracked in [v1-progress.md](v1-progress.md); until the coordinator implements an item, clients must tolerate its absence (for example a missing `grid` or `verified` field).

## Identity
- POST `/sessions` `{join_code,name?,client_name?}` -> `{token,session_id,user:{id,name},balance}`. Creates a **new** anonymous account with the 100-credit sandbox grant. Join code env POCKETGRID_JOIN_CODE defaults `pocketgrid-demo` for local. **(V1)** `name` is optional (1–80 chars); when omitted the server assigns `Guest XXXX`. `session_id` identifies this sign-in for revocation.
- All UI requests use `Authorization: Bearer <session token>`. **(V1)** An account may hold many session tokens (one per signed-in device). Tokens are stored hashed in a `user_sessions` table; tokens issued before the migration keep working. Tokens do not expire; they end on logout or revocation.
- **(V1)** POST `/sessions/link-codes` session `{}` -> `{code,expires_at}`. Issues a single-use code that signs another device into the **same** account. `code` is 10 characters from `23456789ABCDEFGHJKMNPQRSTVWXYZ` (case-insensitive, also typeable), valid 120 s, stored hashed. The client builds the Link QR from its own grid address and the code with `gridLinkPayload` (the coordinator may sit behind a proxy and does not need to know its public address). Issuing a new code invalidates the caller's previous unused codes.
- **(V1)** POST `/sessions/link` no auth `{code,client_name?}` -> `{token,session_id,user:{id,name},balance}`. Redeems a link code for a new token on the existing account and its current balance. No join code needed. An unknown, used or expired code returns 400 `Link code invalid or expired` (one message for all cases). The server rejects further attempts after 5 failures per client address per minute (429).
- **(V1)** POST `/account/credentials` session `{username,password,current_password?}` -> `{username}`. Adds an optional login to the existing account, enabling recovery without another device. `username` 3–40 chars `[a-z0-9._-]`, case-insensitive, unique (409 `Username taken`). `password` 8–200 chars, hashed with `hashlib.scrypt` and a per-user salt. Changing an existing login requires `current_password` (403 otherwise).
- **(V1)** POST `/sessions/login` no auth `{username,password,client_name?}` -> `{token,session_id,user:{id,name},balance}`. New token for the same account. Failure returns 401 `Incorrect username or password` regardless of which part is wrong; same rate limit as link redemption.
- **(V1)** GET `/sessions` session -> `{sessions:[{id,client_name,created_at,last_used_at?,current}]}`. Never returns tokens.
- **(V1)** DELETE `/sessions/{id}` session -> `{ok:true}`. Revokes one of the caller's sessions (404 if not the caller's). POST `/sessions/logout` session -> `{ok:true}` revokes the current one. Revoking a session does not pause or delete devices.
- POST `/devices` `{name,kind:"browser"|"python"|"ios",capabilities:["image_generate"|"image_finalize"],limits:{cpu_threads:2,max_pixels:262144,session_minutes:30}}` -> `{device,token}`. Device begins enabled:false. Owner session required; token is separate device credential. Android registers as `browser`.
- PATCH `/devices/{id}` owner session `{enabled?:bool,limits?:{cpu_threads,max_pixels,session_minutes}}`. Enabling starts timed contribution session. Disabling revokes active lease immediately (worker must cancel). Thread limit applies CPU only, no claim of GPU%/RAM enforcement.

### QR payloads (V1)
QR codes and deep links carry `gipu://join?grid=<url>&code=<join code>` (Invite QR: creates a new account) or `gipu://link?grid=<url>&code=<link code>` (Link QR: joins the existing account). Both values are URL-encoded; `grid` is the absolute `http(s)` coordinator origin. Clients parse payloads locally with `parseGridLink` in `apps/web/src/identity.ts` (iOS mirrors its rules) and never forward the payload itself to a server. A client redeeming a payload for a different grid must call it **without** any existing token, and must ask before replacing a signed-in session. Release builds may embed a default grid address and join code so first launch needs no typing.

## Snapshot UI (poll ~2 sec)
GET `/state` -> `{user:{id,name,username},balance,reserved,earned,grid,devices:[Device],jobs:[Job],events:[Event],ledger:[Ledger],agent:{mode,available},pricing:{generate,finalize,fee},server_time}`. `pricing` is the **current** per-image price from live supply (see Jobs).
- **(V1)** `user.username` is the optional login name or null. `devices` contains only the caller's own devices. `jobs` contains only the caller's jobs (latest 30). `grid:{connected,ready_to_create,ready_to_finish}` counts online devices across the whole grid: `connected` = online; `ready_to_create` / `ready_to_finish` = online, enabled, unexpired sharing session and the `image_generate` / `image_finalize` capability. Offline and stale test devices drop out of every count. No other user's device names or IDs are returned.

Device `{id,owner_id,name,kind,capabilities,enabled,online,limits,session_expires_at,last_seen,active_task_id,telemetry:{backend?,model?,rss_mb?,cpu_percent?,progress?,stage?},earned}`. Session expiry/last_seen may null.
Job `{id,owner_id,prompt,status:"planning"|"queued"|"running"|"completed"|"cancelled"|"failed",count,width,height,steps,budget,reserved,spent,refunded,created_at,tasks:[Task],images:[{task_id,url,variant,stage,verified}],receipt?:{budget,contributor_total,platform_fee,refund,total_charged},plan:{mode,explanation}}`.
- **(V1)** `images[].verified` is true for an accepted `image_finalize` output and false for a generated image awaiting finishing. Clients shimmer an unverified image and show the verified image without effects once present for that variant. `stage` stays the producing task kind.

Task `{id,job_id,kind:"image_generate"|"image_finalize",status:"queued"|"running"|"completed"|"cancelled",variant,prompt,width,height,steps,seed,price,attempts,device_id?,device_kind?,lease_id?,lease_expires_at?,progress,source_url?,source_task_id?,output_url?}`. Live lease IDs are only in worker claim replies, never public snapshots. Generate max 512x512 default256; finalize is an actual pixel check, not AI.
- **(V1)** `device_id` appears only when the assigned device belongs to the caller. `device_kind` (`browser`/`python`/`ios`) always appears for an assigned task so clients can say "a grid laptop" without identifying it.
- **(V1) Finalize output:** a lossless PNG with the same dimensions whose decoded RGB pixels are **identical** to the source. Nothing is drawn on the image. Finishers may add PNG text chunks (`gipu:job`, `gipu:task`); the coordinator ignores ancillary chunks. Replaces the deterministic 4px teal RGB(36,203,166) frame, which remains accepted only during rollout (see Workers).

Event `{id,kind,message,created_at,device_id?,job_id?,user_id?}`. Kinds include job_planning,job_created,task_started,credits_earned,task_reassigned,job_completed,job_failed,job_cancelled,device_paused.
- **(V1)** Returned events either belong to the caller (`user_id` = caller, e.g. own device paused, own credits earned) or concern the caller's own job. Events about the caller's job caused by another user's device omit `device_id` and `user_id` and use a generic message (e.g. `A grid laptop started image 2`). Messages never contain other users' device names, prompts or artifact IDs. Other users' job lifecycle events and other contributors' `credits_earned` are not returned.

Ledger `{id,job_id,kind,amount,created_at,note}`. Positive increases own spendable balance, negative decreases. Reserve is debit; accepted tasks transfer from escrow; unused returns at completion/cancellation. Do not infer balances by summing visible rows.

## Jobs
- POST `/jobs` owner `{prompt,count:1,width:256,height:256,steps:12,budget:10,request_id:"unique-uuid",use_agent:false}` -> Job. count1..4; dimensions256/384/512; steps4..30. Idempotency on(owner,request_id). Quote = count*(generate+finalize)+fee minimum. **Dynamic pricing:** `generate` is 7 credits when 0–1 devices are ready to create, 6 when 2–3 are, and 5 when 4 or more are; `finalize` and `fee` stay 1. The prices are computed when the job reserves its budget and **locked** into `plan.pricing` (visible to the owner); every task of the job, including later finishing tasks and retries, uses the locked prices, so later supply changes never change what the request pays. Jobs created before dynamic pricing keep 6/1/1. Reserve full user budget, one platform fee on successful completion. Guard fixed costs on server even if agent proposes differently. Agent optional Strands Bedrock mode; explicit errors when unavailable, no silent imitation.
- With `use_agent:true`, POST `/jobs` returns promptly with `status:"planning"`, the budget already reserved and `tasks:[]`; it does not wait for the model. A background planner durably claims the request (`plan.planning:{status,attempts,claim_id,started_at}`), runs Strands and either queues tasks (`planning.status:"done"`, job `queued`) or fails the job with a full refund (`planning.status:"failed"`, `plan.dispatch_error` names the error type only). Poll `/state` or GET `/jobs/{id}` for the outcome. Repeating the same `request_id` at any point returns the same job; it never reserves twice. A planning claim lasts 150 s; after a coordinator restart an expired claim is retried, at most three attempts, then refunded. A plan from an expired or replaced claim is rejected. If the server's planner configuration changes before planning, the job fails and is refunded rather than silently running in manual mode. 503 (no reservation) when Strands or its provider credentials are not configured. Manual jobs still return `queued` immediately.
- POST `/jobs/{id}/cancel` owner -> Job, releases remaining escrow; completed work remains paid, no fee for cancelled job. Allowed while `planning`: the full budget is refunded and a later planner submission is rejected.
- GET `/jobs/{id}` -> Job. **(V1)** Requires the owning session, or a device token assigned to one of the job's tasks; otherwise 404.
- GET `/images/{artifact_id}` returns PNG. **(V1)** Requires the session that owns the artifact's job, or a device token whose current or completed task uses the artifact (a finisher reading its source); otherwise 404. UI fetch blob with token (do not put bearer in URLs). Source URL relative `/api/images/...`.

## Buying credits (Stripe test mode)
Money only flows **in**: credits can be bought but never cashed out, refunded to a card or withdrawn; no such endpoint exists. `/state.payments` and GET `/credits/packs` -> `{available,test_mode:true,currency:"usd",packs:[{id,credits,amount}]}` (amount in cents). Packs are fixed on the server: `starter` 50 credits $5, `standard` 120 credits $10, `large` 300 credits $20. `available` is false unless `STRIPE_SECRET_KEY` is a `sk_test_` key; live keys are refused.
- POST `/credits/checkout` session `{pack}` -> `{session_id,url}`. Creates a Stripe Checkout Session for the caller (`client_reference_id` = user) and records a pending purchase. The client opens `url` in the browser.
- GET `/credits/checkout/{session_id}` session (own purchases only, otherwise 404) -> `{status:"pending"|"paid",credits}`. While pending, the coordinator retrieves the session from Stripe and settles it.
- GET `/credits/return?session_id=…` is Stripe's redirect target (a small HTML page); it settles the same way. POST `/stripe/webhook` accepts `checkout.session.completed` / `async_payment_succeeded` signed with `STRIPE_WEBHOOK_SECRET` (HMAC-SHA256, 5-minute tolerance).
- Settlement grants credits **once** per session, only when Stripe reports `payment_status:"paid"`, `livemode:false`, and the same user, amount and currency the coordinator recorded. It adds a `purchase` ledger entry and a `credits_purchased` event.

## Image generation (demo: cloud)
`GET /health` and `/state` include `generation:{mode:"cloud"|"local",model,available}`. With `POCKETGRID_IMAGE_GENERATOR=cloud` (the default whenever `AKAMAI_API_KEY` is set) the pixels come from the Akamai workshop's hosted model `hackathon-image`; `local` uses on-device Tiny-SD. The pipeline is unchanged: a contributor's worker claims the generation task, holds the lease, reports progress, uploads the PNG and earns the task price.
- POST `/tasks/{id}/cloud-image` device token `{lease_id}` -> `{png_base64,model,backend:"cloud"}`. Only for a running `image_generate` task held under that lease (409 stale lease or local mode, 422 other kinds). The coordinator calls the provider with its own key (never stored on devices), requests the smallest supported square size (512) and resizes to the task's exact size, waits on the provider's rate limit (6 images/minute per team) within a bounded budget, and returns 503 when the service is busy or unavailable; the worker then reports a retryable failure. The worker still submits through `/complete`.
- Every image the coordinator generated this way is recorded server-side, and `images[]` carry `generated_in:"cloud"|"device"` and `model`; a finished image carries its generation's label. Clients show "Cloud-generated". Workers choose with `--generator auto|cloud|local` (default `auto`: follow `/health`).

## Workers
All worker requests bearer device token. Persist device id/token across restarts. Auto-share only after explicit owner start (enabled persisted until session expiry).
- POST `/devices/{id}/heartbeat` `{telemetry:{...},task_id?:string,lease_id?:string}` -> `{device,lease_valid:bool}`. Every3s. Renews matching live lease to now+15s. Stop active computation when enabled:false or lease_valid:false. When idle omit task/lease and ignore false.
- POST `/devices/{id}/claim` `{}` -> `{task:Task|null,device:Device}`. max one task/device. Claims only enabled, unexpired session, matching capability+max_pixels. Server returns active existing task for idempotent repeats.
- POST `/tasks/{id}/progress` `{lease_id,progress:0..1,stage:"..."}` -> `{ok:true}` (409 stale lease).
- POST `/tasks/{id}/complete` `{lease_id,png_base64,metrics:{backend?,model?,elapsed_seconds?}}` -> `{accepted:true,duplicate:bool,earned:price}`. server verifies lease, PNG decode/size; settle exactly once. No semantic-proof claim for generated images. **(V1)** For finalize, the server accepts output whose decoded RGB pixels equal the source exactly. During rollout it also accepts the legacy teal frame (border pixels + interior equality) so older iOS/Android builds still settle; `POCKETGRID_ACCEPT_LEGACY_FRAME=0` turns that off, and the legacy path is removed after every client ships the V1 finisher. Deploy the coordinator before shipping finishers that omit the frame.
- POST `/tasks/{id}/fail` `{lease_id,error}` -> `{ok:true}`; retries bounded, excludes just-failed device for next attempt. Expired/revoked leases reassigned; no credits for partial work. Retrying full image generation restarts that image, not a diffusion checkpoint.

## Agent routing and review
Strands jobs also expose `plan.routes` (stage → selected device IDs), `routing_until`, recorded `tools`, and optional `task_routes`, `review` and `reviews`. Initial choices must name enabled, online devices capable of that stage and image size. Preferences last45seconds and are bypassed when no selected worker is available. Finalization receives a fresh window when generation finishes. A failed attempt clears its old preference so healthy fallback workers can claim. Workers use the same claim API; they do not execute model-generated code. **(V1)** In the caller's snapshot, `plan.routes` and `task_routes` keep only the caller's own device IDs; routing event messages follow the Event rule above.

Failure and terminal events trigger a separate background review in the configured provider mode. The agent inspects current tasks, attempts, output references and receipts. It may change preferences for exactly the queued task/attempt set it inspected; stale changes and expired or replaced review claims are rejected. Terminal receipts and completed work are immutable. Each review has a durable150second claim and at most three attempts. Events include `routing_applied`, `routing_updated`, `agent_reviewed` and `agent_review_failed`. Manual mode never invokes a model.

## Apps
Browser/iOS/Android advertise image_finalize only, execute foreground work and cancel on Pause/background. Python worker supports both, preferring generation. Clients show status and the next action; limits, telemetry and receipts live behind Developer options or disclosure. Native notification opt-in only on user tap; **(V1)** `job_completed` for the caller's job triggers a "images ready" notification when permitted. The Mac Tauri UI can explicitly launch a prepared local Python worker with image_generate only, paired to its account. Native connection always pauses the device before claiming; Start (the Create images / Finish images toggle) remains a separate owner action through the existing API. Disconnect stops the local process and requests Pause. CLI workers remain independently supported. Do not claim browser runs diffusion. **(V1)** Session tokens live in platform secure storage where available (iOS Keychain, Android Keystore-backed storage) behind the `SessionStore` interface in `identity.ts`.
